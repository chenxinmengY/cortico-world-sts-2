## 灯是红的 / 连不上

| 现象 | 原因 | 怎么办 |
|---|---|---|
| World 列表里有，但灯一直红 | 游戏没开，或还在主菜单 | 进一局再看。插件每 5 秒重连，会自动接上 |
| `curl http://127.0.0.1:18080/health` 连不上 | NekoSpire 没加载 | 游戏 mod 菜单里确认它启用；缺 **RitsuLib 0.6.0+** 时它不会加载 |
| 端口能连，但 `status` 不是 `ready` | 还在加载存档 / 动画 | 等几秒；一直在就退回主菜单重进一局 |
| 宿主启动就报错，插件加载失败 | `data\extensions\package.json` 写错 | 路径用 `/`，不要用 `\`；`link:` 后面是**目录**不是文件 |

## 她完全不动

按顺序排除，别跳步：

1. **游戏是不是在等输入？** 敌方回合、动画期间不动是正常的。
2. **是不是在主页 / 选角色？** `quietOnMenu` 默认开，这两屏她不会自己开局，要你说一句。
3. **你是不是说过"停"？** 说"继续"。
4. **这一屏是不是没有可选项？** 桥没给动作时她会发一条 `sts-2.blocked` 提醒，然后等你点。
5. **是不是连续被拒了两次？** `maxRejectsBeforeStop` 默认 2，触顶会停手并在面板说一句。

都排除了还不动 → 打开 `devTools`，让她调一次 `sts2_probe`，把输出贴进 issue。这一段会直接显示"桥给了什么动作、她读成了什么"。

## 重复同一个动作 / 卡在同一屏

**最常见的原因：`{select}` 用错了屏。**

`{select: n}` 只能用在"选牌屏"（画面写着「选择 N 张牌」），而且要**一次列全**：

```jsonc
{ "steps": [{ "select": 1 }, { "select": 2 }] }
```

- 在奖励屏、事件屏、选角色屏用了 `{select}` → 桥回 500，看起来像断联；
- 一次只 `select` 一个 → 点同一张牌会**反选**，永远凑不满，于是原地打转（0.1.24 修的就是这个）。

其他可能：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 动作提交了但没生效，还报同一个编号 | 状态码过期 | 让她重读局面（`sts2_observe`）；连续两次就停手 |
| 一直在"结束回合"和"出牌"之间来回 | 战斗里空动作宽限没到就判卡住 | 把 `combatGraceMs` 从 9000 往上调 |

## 越来越卡 / 打着打着断联

**求解器把游戏主线程占满了。**

症状组合：`/state` 从 3ms 涨到 350ms 以上、`/action` 4 秒起步、然后断联。第一层 Boss 最容易触发（0.1.29 就是这个坑）。

处理顺序：

1. `solverPrefetchMs` 调大（比如 5000）——它一次搜索能吃满 0.7 秒 CPU；
2. 还卡就关 `solver`（注记没了，但战斗照打）；
3. 想整场省心，用 `solverAutoplay`，它遇到算不动会**冷却 60 秒**再试，冷却期内一个请求都不发。

## 她打得太莽 / 该防的时候打

先分清是"判断差"还是"信息缺"：

- **判断差**：说一句"稳一点""先防御"。这类话是打断，不是聊天，下一步立刻生效。
- **信息缺**：看回执里有没有 `入射 / 可挡 / 缺口 / 预计剩血`。有这四项还打错，是策略问题；没有这四项，是渲染漏了，去开 issue。
- **求解器接管中**：接管期间她不算账，判断来自桥的求解器。关掉 `solverAutoplay` 就回到模型自己打。

## 台词不出现 / 太吵

| 现象 | 原因 | 处理 |
|---|---|---|
| 一句都不说 | `chatter` 是 `off` | 改 `rare` |
| 偶尔说，但很少 | 默认就是稀疏的 | 调高 `chatterWinChance` / `chatterHurtChance`，缩短 `chatterCooldownMs` |
| 说得太频繁 | 冷却太短 | `chatterCooldownMs` 拉到 120000 |
| 说了但气泡不弹 | 宿主没有直连通道 | 会退回 `murmur`（走模型，慢 2–4 秒）；看 [core-speak.md](core-speak.md) |
| 改了 `chatter.json` 没反应 | 文件路径不对，或 JSON 语法错 | 配置里看 `chatterLinesFile`；JSON 不允许注释和尾逗号 |

## 她抢着点地图（多人局）

`coopRouteWaitMs` 默认 4 秒，队友没投完她就点了。

- 调大（比如 8000）多等一会儿；
- 设 `0` = **一直等队友先投**（队友不投她就一直不点，地图会停在那儿）。

## 回档判错了

| 现象 | 原因 | 处理 |
|---|---|---|
| 篝火回满血被当成读档 | 老版本的误判 | 已在 0.1.6 修；还遇到就发抓包 |
| 明明是 SL 她却没反应 | 读不到存档 | `readSave` 开着时会退回纯内存判定，靠局面差异识别；`savePath` 可手动指定 |
| 换了台机器存档路径不同 | 自动查找失败 | 手填 `savePath` 指向 `current_run.save` |

## 动过手之后就不动了

老版本的坑（0.1.28 修过）：一次被抢占的模型轮，把推送永久卡死。

现在的表现应该是：她不动 → 10 秒后提醒一次 → 再不动就停手说一句。

如果她还是**永远不动**：说"继续"重置一次；还不行就重启宿主。

## 怎么抓一份发给别人的样本

```powershell
cd "<你的插件目录>"; .\scripts\dump-state.cmd
```

- 自动按界面命名（战斗带回合号），落在 `samples\`；
- 同时打印 `界面=COMBAT 动作=7` 这样的摘要；
- **摘要里动作数是 0 → 这一屏读不懂**，这正是最需要的样本。

发 issue 前把 `run_id` 之类的换成 `xxx`，别把自己的局号贴出去。

## 还是不行

开 issue 时带这四样，能省三轮来回：

1. 插件版本（`package.json` 的 `version`）+ 宿主版本；
2. 桥的种类与版本（NekoSpire / 其他）；
3. 出问题的界面 + 当时的 `sts2_probe` 输出；
4. 是"她不动"还是"动了被拒"。
