# 用 dsh-bili-scroll 给 STS2 桌宠采集打法

> 目标：让桌宠从 B 站攻略里学到「求解器覆盖不到」的经验，落成可审、可回滚、可验证的知识库。
> 前置阅读：`docs/handover-consult.md`（token 成本与延迟结构）

---

## 0. 一句话

**把刷 B 站插件从「分析师」降级成「抄写员」**：只要 `时间戳 + 作者原话 + 当时的局面`，不要它的总结和评价。知识库的原子是原话，不是转述。

---

## 1. 为什么是这个角色

插件默认产出（charter v3）是「为什么值得 + 它自己的一句话」= 分析师。问题：

| | 抄写员 | 分析师 |
|---|---|---|
| 输出 | 原文引用 + 时间戳 | 二手总结 |
| 可验证 | 回到视频核对即可 | 只能信或不信 |
| 可自动化 | 能入库、能索引、能埋点 | 只能人读 |
| 误差 | 零（逐字抄） | 转述一次错一次 |

LLM 读字幕再转述，误差会叠加三次：作者说错 → 字幕识别错 → LLM 理解错。抄写员把中间两次消掉。

---

## 2. charter 补丁

插在 `prompts/duty.md` 的 `## 一轮要做的事` 之后、`## 评论与 @ 本人` 之前。

```markdown
## 这一轮的特例：STS2 打法采集（覆盖上面的「判据」和「产物」）

这一轮不是给使用者挑视频看，是给一个玩《杀戮尖塔 2》的桌宠采集打法。
你的角色是**抄写员**：只抄他说的原话，不总结、不评价、不补画面。

### 判据（替换默认那条）

留下：视频里**真的在出牌**，并且**出声解释了为什么**（"这里该先上毒""别急着打"这类）。
丢掉：纯萌新实况、纯剪辑集锦、只说"好强"不说理由的、卡组展示但无实战的。

### 每条视频要抄什么

在 `### BV号` 段落里、**档位**那一行之后，追加一个 YAML 块
（⚠️ 不要再加 `###` 标题 —— 宿主数的就是 `###` 行数，加了会吃掉当天配额）：

```yaml
sts2:
  deck: 毒 / 力量 / 防战 / 不明
  act: 1-3
  enemies: [腐化的哨兵, 观察者]
  points:
    - t: "12:34"
      quote: "这里别急着上毒，他 T3 才上 buff"
      his_play: "格挡"
      situation: "T2 敌 intent=buff 我方毒 6"
```

规则：

- 每条视频最多 8 条 `points`，只抄**有解释**的决策，没解释的省略
- `quote` **逐字抄字幕原文**，≤40 字；不改写、不润色、不加你的判断
- `t` 用字幕自带的时间戳；没有时间戳就写 `null`
- 抄不出 3 条以上 → 这条视频标「无结构化增量」，不写 YAML 块
- **画面里能看出、字幕里没说的（比如他打的是哪张牌）→ 不要补**，你没有画面理解能力
- 一条 `points` 里如果作者说了多个理由，只抄**跟出牌直接相关**的那半句
```

### 为什么不能加新标题

charter 写死了：`### BV…` 的行数 = 这一轮挑中的条数，宿主拿它跟「每天最多几条」对账。多一个 `###` 就多吃一格当天配额。

## 4. 设置页

| 项 | 值 | 理由 |
|---|---|---|
| 日报写多细 | 完整 | 薄版会丢 YAML 块 |
| 每天最多挑几条 | 5–8 | 深度优先 |
| 峰谷自动刷 | 开 | 读字幕是 token 大头，谷时省一半 |
| 自动评论并 @ 你 | **关** | 不需要 |
| 回复评论 | **关** | 不需要 |
| 人设提示词 | 「你是数据标注员。只输出 YAML，不写感想、不寒暄。」 | 提高可解析率 |
| 本地转写 | 可开 | 对无人声视频无效，但对有语音无字幕的有效 |

## 5. 现实约束：覆盖率

**这是整套方案的天花板，先认清：**

- 插件只读字幕，不看画面。没字幕 = 跳过（报告里会写「因无字幕跳过 N 条」）。
- STS2 的 B 站内容大量是无人声实况 + BGM，字幕为零，本地转写也转不出东西。
- 预计有效覆盖率 **10–20%**。一轮搜 20 条，产出 2–4 条可用。

这个量级够用：一天 3 条，一个月 90 条，足以覆盖 Act1 大部分精英的应对。

---

## 6. 两条路线的分工（重要修正）

早前设想的「字幕语料过求解器对撞」**在字幕路线上做不干净**。

原因：求解器要结构化 state（`hand[] / energy / enemy{hp,intent}`），字幕给的是自然语言（"这里别急着上毒"）。两者对不齐，没得对撞。

| 路线 | 拿到什么 | 自动验证 | 成本 |
|---|---|---|---|
| 字幕（bili-scroll） | 人类经验的自然语言 | **不能**，靠人审 + 埋点 | 极低，现成 |
| 画面反推（自建） | `(state, action, result)` | **能**，过求解器 | 高 |

**先字幕，后画面。** 对撞只在画面路线上成立。

---

## 7. 字幕路线的验证（降级方案）

1. **人审 10 分钟/天**：插件给的是原话 + 时间戳，点开核对成本很低。判断三件事：
   - 这条原话在说什么，我能不能复述成一个规则
   - 这条规则和求解器的覆盖范围是否重叠（重叠 = 没增量）
   - 是否依赖特定遗物/种子（依赖 = 降权）
2. **实战埋点**：条目进 `confirmed` 后记录「触发次数 + 触发后胜率变化」。样本 ≥20 次再决定留不留。

## 8. 条目 schema

```yaml
- id: sts2.watcher.t2-burst
  scope:
    deck: poison
    act: [1, 2]
    enemies: [corrupt_sentinel, watcher]
  when: "T2 敌方 intent=buff 且 poison_stack >= 6"
  do: "本回合不叠毒，先格挡到 T3 再爆发"
  why: "它 T3 自身上 buff，爆发窗口在 T3"
  source:
    kind: video
    ref: BV1xxxxxxxx
    at: "12:34"
    author: "xxx"
    quote: "这里别急着上毒，他 T3 才上 buff"
  verified:
    reviewer: user
    samples: 0
    win_delta: null
  version: { game: sts2, patch: "0.x" }
  status: candidate        # candidate | confirmed | retired
```

三层物理隔离：

```
inbox/2026-10-23.yaml    ← 插件产出，未审
strategy.yaml            ← 审过，带 source + verified
（运行时只读 strategy.yaml，永不读 inbox）
```

## 9. ingest 骨架

```ts
// tools/ingest.ts
type Point = { t: string | null; quote: string; his_play: string; situation: string };

// 1. 解析 out/<date>.md 里的 ```yaml 块（挂在 ### BV 段落下面）
// 2. 每条 point → 一条 candidate 条目，带上 source.quote
// 3. 按（敌人, 回合, 关键词）聚类，同义条目合并，保留最早的 source
// 4. 写 strategy.yaml，status=candidate
```

要点：

- **解析失败率必须为 0 才能往下走**。第 3 步的验证点就是「YAML 块能不能 100% 解析」。
- 聚类用关键词匹配就够，别上模型（省 token，也好调试）。

---

## 10. 运行时注入

不要塞静态前缀。构建快照时本地检索：

```
输入：当前敌人 id / 遗物 / 卡组标签 / 回合数
检索：strategy.yaml 里 status=confirmed 且 scope 命中
注入：top-2，每条 ≤40 token，放快照尾部
优先级：低于「求解器：下一步 → N」那一行
```

求解器是精确的，策略是经验。冲突时求解器赢。

---

## 11. 落地顺序

| 步 | 做什么 | 工作量 | 验证点 |
|---|---|---|---|
| 1 | 装插件、扫码、填关键词 | 10 min | 设置页能跑「现在跑一轮」 |
| 2 | 打 charter 补丁 | 10 min | 日志无 charter 冲突告警 |
| 3 | 手动跑一轮，看 YAML 块 | 5 min | **100% 可解析** |
| 4 | 写 ingest | 半天 | candidate 条目落盘 |
| 5 | 写运行时检索 | 半天 | 快照尾部出现策略行 |
| 6 | 跑一周，每天审 10 min | — | confirmed 累积 |
| 7 | 埋点统计触发效果 | 1 天 | win_delta 有数 |

第 3 步是唯一的硬门槛。YAML 解析不了，后面全是空转。

---

## 12. 别做的

1. **别让插件直接产出策略条目并进实战** —— 它是抄写员，入库要人审。
2. **别把 inbox 和 strategy.yaml 混在一起** —— 原始素材和生效规则必须物理隔离。
3. **别做全量注入** —— 超过 200 条必须检索，否则前面所有 token 优化全废。
4. **别用视频学基础牌效** —— wiki 一次性搞定，不会过时。
5. **别把 `###` 当 YAML 的标题用** —— 会吃掉当天配额。
